  writing "Cut" as if it were a settled decision was wrong, and the drift

  The distinction that matters: the broker problem was about a queue holding
  pending state with no other source of truth — lose that write and the URL is
  gone, full stop. index.jsonl isn't that. It's derived from urls.content_hash,
  which is the actual source of truth; the file is a projection you could

  file and the DB is a staleness bug, fixable by re-running the projection — not
  a lost fact. That's a materially weaker failure mode than what killed the
  Redis case, and I shouldn't have reached for the same argument.
